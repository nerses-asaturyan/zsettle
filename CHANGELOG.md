# Changelog

## Unreleased

- Public demo: `zsettle-app --public` serves many visitors (their own wallets, passkey or code-and-passphrase sign-in, session cookies, a shop each behind a relay, a self-restocking house shop that hands out test coins once), with a one-command server setup (`deploy/setup.sh`, Caddy, systemd) and a project page in `docs/index.html`; backup words for passkey wallets.
- `zsettle-app`: a local web page over the two binaries, with a wallet unlocked by a passkey (WebAuthn PRF) or a passphrase, a market that opens a seller's shop by address and checks its signature, one-click buying with live steps, minting, listing, the shop with its offer feed, item histories and an activity log; it listens on localhost only, behind a per-launch token, Host and Origin checks and a strict content security policy.
- Two-party atomic settlement core: one Ironwood transaction with spends under two full viewing keys, proven by the buyer, signed per party, extracted and broadcast.
- Buyer CLI: `list`, `sync`, `import-listing`, `buy`, `finish`, `broadcast`, `verify`.
- Seller service: `sync`, `mint`, `items`, `publish`, `sign`, `serve`.
- Seller policy with tests: expiry bounds (set, after the tip, within the limit), single item spend, no extra seller spends, payment check.
- Seller service hardening: built-in wallet sync before every pass, listings reconciled with the wallet's recorded spends, proof verification before signing, every acceptable offer signed (no lock to grief), replies named by envelope content, size cap and per-envelope quarantine, atomic writes, idempotent restart, retry with backoff.
- Privacy: the new item note is encrypted to the buyer's outgoing key and sent to a fresh diversified address; the payout address is derived for the market; listings publish the Orchard viewing key only; the seller copy carries no value trapdoors; expiry and fees are the ecosystem defaults.
- Signed listings: buyers verify the file against the published viewing key.
- Resale: items can be received into a dedicated item account and relisted; `verify` follows an item across holders when given each holder's listings.
- Consensus guard: build, mint and broadcast stop when the server is on a branch this build does not sign for.
- Provenance verification from compact blocks with viewing keys only, starting at the genesis block; `--private` scans from the birthday instead.
- Follow-up to the proxy review: the tool's proxy check is the only reader of the proxy variables (an empty one no longer breaks every request); the seller copy is an ordinary file again, since a shared inbox may belong to another user; the docs say a proxy applies to every host.
- Review of the listings-by-URL and service changes: a proxy named in the environment must be usable or the command stops instead of connecting directly (`socks5h://` accepted); a redirected listings URL is reported as such; the reply file and the seller copy are owner-only; the deferral clock ignores a tip of zero; filed duplicates keep their extension so the daily cleanup removes them, and a re-post of already filed bytes is dropped; the docs say what fetching listings by URL reveals.
- Privacy audit of the service (no leak found): a re-posted envelope is judged afresh (its old refusal is dropped, and an envelope under judgement answers "pending" rather than a stale reason); envelopes are judged in arrival order and a deferral is given up after ten blocks, so the deferral cap is harder to capture; a storage failure answers a fixed text; refusal texts no longer print the seller's tip; the seller copy clears the output proprietary fields; `mint` refuses item values below the minimum.
- Usability pass: an install section, and every release archive carries the docs, spec, examples and licences, with a macOS x86_64 build added; every `--listings` reads `ZSETTLE_LISTINGS` and accepts the URL a running service serves the file at, fetched and verified without touching the disk; `buy` saves the reply URL beside the trade file and `finish` reads it when `--signed` is omitted; `init` writes `env.ps1` next to `env.sh`, and the seller's names the listings file; `zsettle-seller pay` cashes out from the payout account; `--account` defaults from the environment; `notes` and `items` show ZEC; the docs state the funding amounts and the mint fee rule, and the verify example in TRADE.md is pasteable.
- Release binaries are stripped of debug symbols: tens of megabytes instead of 230 MB each.
- Amounts in ZEC or zatoshis everywhere (`--price 0.001`); `init` writes `env.sh` to source; tags publish GitHub Releases with the binaries.
- Post-fix audit (no leak found): a pass defers at most 100 envelopes, refusing the rest, so unproven envelopes cannot fill the inbox; reason files are pruned with the filed envelopes; a seller that has not synced defers instead of refusing; the payout address must be an external-scope address; the docs describe the extra-spend rule as the code applies it (the listed item account's notes).
- Re-audit after the oracle fix: the seller policy now decides on public data only (an output is payment only to the listed address; the extra-spend set is the listed account's own notes), so neither a sibling address of the payout account nor another consignment's note can be probed; deferrals are bounded by the longest listed expiry; `pay` refuses non-Orchard recipients; signed replies are deleted with the filed envelopes after a day; error replies carry a fixed text; the proof cache is capped; `GET /reply` answers 410 instead of "pending" forever when a refusal's reason was not kept.
- Second usability pass: `init` prints `export` lines and every wallet command reads `ZSETTLE_WALLET`, `ZSETTLE_IDENTITY`, `ZSETTLE_ITEM_ACCOUNT`, `ZSETTLE_PAYOUT_ACCOUNT`, `ZSETTLE_BUYER_ACCOUNT` and `ZSETTLE_LISTINGS`, so the identity flags are typed once; `mint` takes several `--name` and makes all the items in one transaction; a clear message when the payout account has no spendable note; `verify --item` accepts any note of the item; the quickstart waits a block and syncs between mint and publish; one key-file convention in every document; the mainnet table in TRADE.md is whole again.
- Privacy audit: the service judges an envelope in three stages (public checks, proof, then the checks that use its own keys), so refusals before the proof can no longer be used as an oracle for the seller's notes; full and final PCZT files are owner-only; `buy` warns on a non-default expiry; reservations stay until `rotate` retires them; `verify` reads its stream to the tip; birthdays are rounded to a thousand blocks; filed envelopes are deleted after a day; no `Server` header; `buy` and `finish` honour `HTTPS_PROXY`/`ALL_PROXY` (Tor); docs say what the envelope and the two-action shape reveal.
- Usability pass after an independent walkthrough: `pay` sends ZEC out (or funds a counterparty); `mint` prints the item note reference; `--seller-copy` is optional with `--seller-url`; `items` takes only the wallet and the item account; the service serves `GET /listings`; `list` shows prices in ZEC; the README flow can be followed as printed (sync, names, the confirmation wait, key files kept apart); a release workflow builds binaries for Linux, macOS and Windows.
- Found on mainnet: a seller that also holds imported viewing keys refused offers paid from a note of a viewed account; the extra-spend check now counts only accounts the wallet can spend from.
- Mainnet run of the shipped code: consignment mint `70b4a0e5…ffb3` and trade `b378dfbc…ea9c` over HTTP; recorded in docs/TRADE.md.
- Second hardening pass: the HTTP endpoint is the service's own code with timeouts, a head cap and bodies refused before they are read (the library used before could be made to abort the process with one bogus Content-Length); the transparent-address filter matches the gRPC method path under any server path prefix; `cancel` keeps the item in the spending action (lineage) and uses the smallest fitting payout note; the service runs its cheap checks before the proof and never verifies a deferred envelope twice; refused envelopes are deleted and only their reasons kept; `keys.toml` and the reservations file are owner-only; the passphrase is held in zeroising memory and not passed to a sync command; self-transfers (`rotate`, `consolidate`, change of `cancel`) go to the change address, so the wallet spends them after the confirmations it asks of change; `consolidate` leaves item notes alone and `buy` receives items into the wallet's item account by default.
- New wallet directories are owner-only on Unix; the HTTP endpoint caps waiting offers at 1,000 and sends no `Server` header.
- Offers over HTTP: `serve --listen` takes `POST /offer` and answers `GET /reply/<tag>`; `buy --seller-url` posts the envelope and `finish --signed <url>` polls for the signed copy, so buyers share no folder.
- Hardening pass: transparent addresses never reach the light server (`Shielded` channel, tested); `cancel` ends a listing for good, `publish --remove` delists, `consolidate` merges small notes; the service defers offers whose anchor or expiry it cannot judge yet; `rotate` syncs first and keeps an offer only while the next block can still mine it; the inbox ignores symlinks; warnings for an index-0 item account, a multi-item consignment and a resale without `--receive-account`; wording on what the listings file and the light server learn.
- `init`, `accounts` and `address` on both binaries: wallets are created by the tools themselves (mnemonic, age identity, database, accounts), so zcash-devtool is no longer needed. Without `--identity` the mnemonic is protected by a passphrase instead of a key file. Logs are quiet unless `ZSETTLE_LOG` is set.
- Third review pass: `publish` verifies the file before signing it again unless `--resign-unverified` is passed, and checks every entry; a spend with unknown expiry counts for 40 blocks after it was first seen, as in the wallet library; an envelope the wallet cannot judge yet is deferred instead of rejected; quarantined files never replace earlier ones; a file dated in the future no longer waits forever; `--expiry-delta` is capped at 40; one server round trip per consensus check; a zero spend randomizer is covered by a test.
- `rotate` retires the paying notes of offers that did not settle; `new-item-account` gives an item its own consignment.
- Second review pass: anchor must be a recent wallet root, dust outputs do not count as payment, envelope branch id checked, zero randomizers refused, account index checked against the account key, seller-side listings verified before re-signing, issued-at height in the signed listings, lineage-broken status in verify, examples for a wallet-free run.
