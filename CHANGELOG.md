# Changelog

## Unreleased

- Ownership proofs are non-interactive (format version 2): `prove` signs the note, the item key and the last scanned block's height and hash, so a proof is made once and shared like an address, and `check-proof` accepts it while that block is on its chain and recent (`--max-age`, default 100 blocks). An optional signed `--label` names the holder; `--challenge` is now optional and turns a proof into a live check. The app's proof sheets follow: share by default, live check optional. Version 1 proofs are refused with a request for a new one.
- Docs, from the same red team: the "transparent addresses are never sent" and on-chain-indistinguishability claims now state what the code actually enforces (and that a non-default confirmation count is a fingerprint); the ownership-proof pages add the relay limitation, the height it reveals, and that ZEC stays private only with a separate item account; the security page documents why reusing the item key to sign messages is safe and that delisting does not cancel signed offers; the protocol spec notes the item pairing is enforced by the buyer, not the seller.
- Security hardening from an independent crypto red team: `publish` refuses an expiry limit above the default (no long free option for a buyer); the paying note is reserved before its offer leaves the wallet; the manual `sign` applies the same action-count cap as the service; `check-proof --private` hides the checked item from the lightwalletd server; the signed listings and ownership-proof structures reject unknown fields.
- App: a darker, blurred backdrop behind sheets, so a sheet no longer looks like it overlaps the balance card on a phone; an ownership proof can be shared straight to a messaging app.
- New items show as arriving right after they are created, before their block, like a bought item does.
- Hosted server: API calls are counted per signed-in wallet (per visitor only before sign-in), so people behind one shared address do not block each other; a wallet is removed only after a fresh look at the chain finds nothing; a faucet payment cut short by a restart is judged only once the wallet is an hour old; the `passkey:` passphrase shape needs a real credential id; a failed offer says whether the coins were freed or stay set aside.
- A note of an unmined transaction is counted only while that transaction can still be mined; the change of an expired or rejected payment no longer shows in the balance.
- The wallet records the transactions it builds itself (a trade, a rotation, a cancel) as soon as they are sent: the balance is right at once, change shows as settling, and a payment made meanwhile cannot pick a note that is already spent.
- App: a passkey wallet confirms every transaction with the passkey ("Confirm with passkey"); the balance card shows coins leaving after a purchase; a seller with an open shop sees confirmations (`zsettle height`); an ownership proof is shown as a QR code and the checker can scan it.
- Tracing stops at the item's first block when the note is not there, instead of reading the chain to its tip; `zsettle check-proof` bounds the challenge like `prove`; the app checks proofs only for an unlocked wallet, a few a minute, and writes the proof file only when the check runs.
- A failed offer no longer locks the buyer's coins: when the seller never received it the note is released at once, when the seller saw it the note moves to a fresh one (`zsettle rotate --abandon <note>`, `--release <note>`), and a reservation whose offer expired is retired after the next sync.
- Faucet: the payment's transaction is written before it is broadcast, so a paying process that is lost resends it instead of paying twice; payments cut short by a restart are looked at when the server starts, and a wallet that received nothing gets its chance back.
- Hosted server: wallets nothing happened to are removed after a day (a synced but empty wallet included), new wallets are also limited per wider network, API calls are limited per visitor, the `passkey:` passphrase shape is accepted only with a passkey, job errors carry no server paths, and listing names are at most 80 characters.
- App: every transaction (a purchase, a payment, creating items, cancelling offers) has a confirm step that shows the cost and says it cannot be undone; a result screen's icon and title follow the outcome, so a proof that does not hold shows a warning, not a tick.
- App: the balance card counts confirmations per note, 10 for a note from another wallet and 3 for the wallet's own change (ZIP 315's recommended policy), and "not enough spendable ZEC" says what is still confirming and for how long; the dot in the top bar opens a Network sheet that says what syncing does.
- App and hosted server: the wording no longer calls a hosted server a demo; the Market says what a seller signs and why the wallet checks it; the ownership texts say exactly what a proof reveals (the item account's viewing key, not the ZEC or payout address); twice as many item icons; the Activity page keeps the explorer note to the link itself.
- CLI: `zsettle notes` marks change notes.
- Hosted demo: 5 new wallets an hour and test coins 4 times a day per visitor address, so several people behind one address can try it the same day.
- Hosted demo: the house shop sells a small catalogue (concert tickets, passes, prints, keys, collectibles) with different icons, descriptions and prices instead of identical tickets; items listed earlier get their details too.
- App: the balance card says when coins are on their way (a faucet payment or a sale the wallet has not seen yet) and when they are still confirming, with the blocks and minutes left; the demo banner shows the wallet code only to passphrase wallets, which need it to sign in.
- App: each tab has an address (`#market` and so on), so the back button returns to the previous tab and closes an open sheet; a sheet keeps focus itself unless it has a field.
- App, accessibility pass: a separate colour for accent text so links, prices and the active tab read on the light theme too (4.5:1); muted and success colours darkened on light; 44 px touch areas for the sync chip, copy and switch controls, links and small buttons; 12 px tab labels; relative dates for a week, then short dates; a wallet heading for screen readers; the ownership check as a list row; sheets take focus themselves; a browser-safe stylesheet (a mangled rule had dropped the phone list styles).
- App: the welcome page notices a browser built into another app (where passkeys usually fail), explains how to open the page in a real browser, and shows the passphrase sign-in at once; passkey errors say what to do; the page tells browsers not to recolour it.
- App: a shop its owner never closed opens again when the owner signs in after a restart of the server.
- Items can carry a short description and an icon (one emoji), signed with the listings file (`publish --description --icon`); the app shows them and has an icon picker.
- Ownership proofs in the app: "Prove I own it" on an item, and a check in the market that hands out a fresh challenge.
- Hosted demo: a new wallet is sent its test coins right away; the page can be installed on a phone's home screen.
- Ownership proofs: `zsettle-seller prove` signs a proof that you control an item note right now, bound to a challenge the checker chose; `zsettle check-proof` verifies the signature and the challenge, then checks on chain that the note is unspent and owned by the proof's key. The proof reveals the item account's viewing key, not ZEC balances or the payout address.
- Documentation book (`book/`, mdBook): guide, CLI, how it works, privacy, security, hosting and reference; published with the project page. App screenshots in the README.
- Second review of hosted mode, all findings fixed: the faucet never loses a chance or pays twice, paused shops keep serving listings and buyers retry short outages, wrong tries count per visitor, state files are replaced whole, visitors counted by IPv4 address or IPv6 /64, unused wallets removed, job and proving limits checked under one lock.
- App: the demo welcome explains a trade in three steps; the demo market lists its open shops first; a buy shows its fee and a sale its price in the activity log.
- Public demo: `zsettle-app --public` serves many visitors (their own wallets, passkey or code-and-passphrase sign-in, session cookies, a shop each behind a relay, a self-restocking house shop that hands out test coins once), with a one-command server setup (`deploy/setup.sh`, Caddy, systemd) and a project page in `docs/index.html`; backup words for passkey wallets.
- `zsettle-app`: a local web page over the two binaries, with a wallet unlocked by a passkey (WebAuthn PRF) or a passphrase, a market that opens a seller's shop by address and checks its signature, one-click buying with live steps, minting, listing, the shop with its offer feed, item histories and an activity log; it listens on localhost only, behind a per-launch token, Host and Origin checks and a strict content security policy.
- Two-party atomic settlement core: one Ironwood transaction with spends under two full viewing keys, proven by the buyer, signed per party, extracted and broadcast.
- Buyer CLI: `list`, `sync`, `import-listing`, `buy`, `finish`, `broadcast`, `verify`.
- Seller service: `sync`, `mint`, `items`, `publish`, `sign`, `serve`.
- Seller policy with tests: expiry bounds (set, after the tip, within the limit), single item spend, no extra seller spends, payment check.
- Seller service hardening: built-in wallet sync before every pass, listings reconciled with the wallet's recorded spends, proof verification before signing, every acceptable offer signed (no lock to grief), replies named by envelope content, size cap and per-envelope quarantine, atomic writes, idempotent restart, retry with backoff.
- Privacy: the new item note is encrypted to the buyer's outgoing key and sent to a fresh diversified address; the payout address is derived for the market; listings publish the Orchard viewing key only; the seller copy carries no value trapdoors; expiry and fees are the ecosystem defaults.
- Signed listings: buyers verify the file against the published viewing key.
- Resale: items can be received into a dedicated item account and relisted; `verify` follows an item across holders when given each holder's listings.
- Consensus guard: build, mint and broadcast stop when the server is on a branch this build does not sign for.
- Provenance verification from compact blocks with viewing keys only, starting at the genesis block; `--private` scans from the birthday instead.
- Follow-up to the proxy review: the tool's proxy check is the only reader of the proxy variables (an empty one no longer breaks every request); the seller copy is an ordinary file again, since a shared inbox may belong to another user; the docs say a proxy applies to every host.
- Review of the listings-by-URL and service changes: a proxy named in the environment must be usable or the command stops instead of connecting directly (`socks5h://` accepted); a redirected listings URL is reported as such; the reply file and the seller copy are owner-only; the deferral clock ignores a tip of zero; filed duplicates keep their extension so the daily cleanup removes them, and a re-post of already filed bytes is dropped; the docs say what fetching listings by URL reveals.
- Privacy audit of the service (no leak found): a re-posted envelope is judged afresh (its old refusal is dropped, and an envelope under judgement answers "pending" rather than a stale reason); envelopes are judged in arrival order and a deferral is given up after ten blocks, so the deferral cap is harder to capture; a storage failure answers a fixed text; refusal texts no longer print the seller's tip; the seller copy clears the output proprietary fields; `mint` refuses item values below the minimum.
- Usability pass: an install section, and every release archive carries the docs, spec, examples and licences, with a macOS x86_64 build added; every `--listings` reads `ZSETTLE_LISTINGS` and accepts the URL a running service serves the file at, fetched and verified without touching the disk; `buy` saves the reply URL beside the trade file and `finish` reads it when `--signed` is omitted; `init` writes `env.ps1` next to `env.sh`, and the seller's names the listings file; `zsettle-seller pay` cashes out from the payout account; `--account` defaults from the environment; `notes` and `items` show ZEC; the docs state the funding amounts and the mint fee rule, and the verify example in TRADE.md is pasteable.
- Release binaries are stripped of debug symbols: tens of megabytes instead of 230 MB each.
- Amounts in ZEC or zatoshis everywhere (`--price 0.001`); `init` writes `env.sh` to source; tags publish GitHub Releases with the binaries.
- Post-fix audit (no leak found): a pass defers at most 100 envelopes, refusing the rest, so unproven envelopes cannot fill the inbox; reason files are pruned with the filed envelopes; a seller that has not synced defers instead of refusing; the payout address must be an external-scope address; the docs describe the extra-spend rule as the code applies it (the listed item account's notes).
